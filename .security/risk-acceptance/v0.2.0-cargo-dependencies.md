## Decision

audit and does not waive future review. No finding is in the current CISA Known Exploited
Vulnerabilities catalog, no finding has a common authoritative safe version available within the
resolved upstream dependency chain, and the audit has zero blocking findings. Reachability is not
claimed absent.

## Mitigations and controls

- The affected packages are inherited transitively through `amtrak-gtfs-rt` or
  `gtfs-structures`; replacing them requires upstream API/dependency work rather than a safe
  same-chain version bump.
- The shipped container is scratch-based, package-manager-free, read-only except for `/data`, and
  runs as UID/GID `10001` with no shell or general-purpose diagnostic tooling.
- Network exposure is loopback-only by default. A wildcard bind fails closed without an explicit
  transport-peer allowlist, and forwarding headers never establish identity.
- The exact local release image passed the complete live/recovery harness, including startup
  guards, peer authorization, artifact decoding, durable recovery, and a zero-match Grype scan.
  Its SPDX SBOM is non-empty (90 packages). Grype's result does not erase Cargo findings.
- The Rust gate passes formatting, Clippy with warnings denied, 57 deterministic tests, and
  rustdoc with warnings denied. Two live endpoint tests remain intentionally ignored in the
  offline suite; the container harness exercises the live feed path.
- The release workflow independently builds, starts, inventories, and scans the exact native
  `linux/amd64` and `linux/arm64` digests before any semantic tag or GitHub Release is created.

## Review triggers

Revoke and re-audit this acceptance on any Cargo lockfile or direct-dependency change, a new CISA
KEV match, a newly published authoritative fix, evidence of reachability/exploitation, a failed
platform scan or smoke test, or expiry. A corrected release uses a new patch tag; published tags
and digests are never rewritten.
